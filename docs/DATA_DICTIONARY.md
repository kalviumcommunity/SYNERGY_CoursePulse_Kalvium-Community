# Data Dictionary

## Dataset Overview

This dataset contains customer transaction and platform event records for the
**CoursePulse / Kalvium Community** analytics platform. It is the canonical
source of truth for all downstream analysis, dashboards, and ML models.

| Property | Value |
|----------|-------|
| **Last Updated** | 2026-08-21 |
| **Maintained By** | Data Engineering Team |
| **Update Frequency** | Daily (transactions) / Monthly (segments) |
| **Primary Key** | `customer_id` |
| **Source System** | CRM + Platform Event Logger |

---

## Task 1 — Column Definitions

### `customer_id`
- **Type**: Integer
- **Business Meaning**: Unique customer identifier from the CRM system — links all transactions and events to a single customer record
- **Example**: `12456`
- **Null Handling**: Never null — primary key assigned at CRM account creation
- **Related KPI**: Customer tracking, lifetime value calculation
- **Updates**: Assigned once when customer account is created in CRM

---

### `trnx_amt`
- **Type**: Float
- **Business Meaning**: Revenue generated by a single completed purchase transaction
- **Example**: `150.99`
- **Unit**: USD
- **Null Handling**: Very rare — investigate immediately if found; may indicate payment processing failure
- **Related KPI**: Monthly revenue, average transaction value, customer lifetime value
- **Updates**: Set at the moment the transaction is completed

---

### `purchase_date`
- **Type**: Datetime
- **Business Meaning**: Date and time the sale was completed and revenue was recognised by the business
- **Example**: `2025-01-15 10:32:00`
- **Unit**: UTC timestamp
- **Null Handling**: Never null — if missing, transaction record is corrupt
- **Related KPI**: Sales velocity, revenue trend, cohort analysis
- **Updates**: Set at transaction completion; convert to local timezone for user-facing reports

---

### `cust_segment`
- **Type**: String
- **Business Meaning**: Customer market segment — determines go-to-market strategy, pricing tier, and sales approach
- **Valid Values**: `B2B` | `B2C` | `SMB`
- **Example**: `B2B`
- **Null Handling**: If null, classify as `UNKNOWN` — never drop the row
- **Related KPI**: Segment profitability, segment churn rate, segment revenue
- **Updates**: Refreshed monthly by the CRM classification job

---

### `flag_churn`
- **Type**: Integer (binary)
- **Business Meaning**: Whether the customer cancelled or stopped purchasing within 90 days of this transaction
- **Valid Values**: `0` (retained) | `1` (churned within 90 days)
- **Example**: `0`
- **Null Handling**: Should never be null for completed transactions; default to `0` if missing with a warning
- **Related KPI**: Churn rate, retention rate, churn model accuracy
- **Updates**: Computed quarterly — historical label, not a real-time flag

---

### `event_type`
- **Type**: String
- **Business Meaning**: The specific action the user performed on the platform — drives engagement and funnel conversion analysis
- **Valid Values**: `search` | `preview` | `enrollment`
- **Example**: `enrollment`
- **Null Handling**: Treat as `unknown` if null — do not drop
- **Related KPI**: Engagement rate, funnel conversion rate, feature adoption
- **Updates**: Logged in real-time by the platform event system

---

### `course_id`
- **Type**: String
- **Business Meaning**: Unique identifier for the course the user interacted with — links to the course performance catalogue
- **Example**: `CRS_101`
- **Null Handling**: Null for `search` events where no specific course was selected — expected behaviour
- **Related KPI**: Course popularity, enrolment count, revenue by course
- **Updates**: Assigned when course is published to catalogue; stable reference key (use over `course_name`)

---

### `course_name`
- **Type**: String
- **Business Meaning**: Human-readable display name of the course used in stakeholder reports and dashboards
- **Example**: `Full Stack Web Development`
- **Null Handling**: Null for search events — expected; join to course catalogue using `course_id` for completeness
- **Related KPI**: Product revenue, enrolment count, course profitability
- **Updates**: May change over time (rebranding) — always use `course_id` as the stable join key

---

### `category`
- **Type**: String
- **Business Meaning**: Broad learning domain used for catalogue segmentation, content gap analysis, and personalisation
- **Example**: `Web Development`
- **Valid Examples**: `Web Development` | `Data Science` | `Cloud Computing` | `Software Architecture`
- **Null Handling**: If null, label as `Uncategorised` for reporting
- **Related KPI**: Category revenue, category demand, content gap analysis
- **Updates**: Set when course is published; reviewed quarterly

---

### `days_since_last_purchase`
- **Type**: Integer
- **Business Meaning**: Recency metric — number of days since the customer's most recent transaction; key input to churn prediction models and re-engagement campaigns
- **Example**: `417`
- **Unit**: Days
- **Null Handling**: Null means no purchase history found — treat as maximum recency (highest churn risk)
- **Related KPI**: Recency score, churn risk tier, win-back campaign targeting
- **Updates**: Recomputed on every pipeline run; value increases every day without a purchase

---

## Task 2 — Column to KPI Mapping

### Monthly Revenue
- **Formula**: `SUM(trnx_amt)` grouped by month of `purchase_date`
- **Related Columns**: `trnx_amt`, `purchase_date`
- **Why It Matters**: Tracks total company revenue — the primary financial health metric
- **Update Frequency**: Daily
- **Owner**: Finance & Revenue team

---

### Sales Velocity
- **Formula**: `COUNT(transactions) / days_in_period`
- **Related Columns**: `purchase_date`, `customer_id`
- **Why It Matters**: Measures transaction activity rate and sales momentum; a drop signals pipeline slowdown before it shows in revenue
- **Update Frequency**: Weekly
- **Owner**: Sales Operations

---

### Segment Revenue
- **Formula**: `SUM(trnx_amt) GROUP BY cust_segment`
- **Related Columns**: `trnx_amt`, `cust_segment`
- **Why It Matters**: Identifies which market segments generate the most revenue — informs resource allocation and pricing strategy
- **Update Frequency**: Monthly
- **Owner**: Strategy & GTM team

---

### Churn Rate
- **Formula**: `SUM(flag_churn) / COUNT(DISTINCT customer_id)`
- **Related Columns**: `flag_churn`, `customer_id`
- **Why It Matters**: Critical retention metric — even a 1% improvement in churn rate can significantly increase ARR
- **Update Frequency**: Quarterly
- **Owner**: Customer Success

---

### Course Enrolment Rate
- **Formula**: `COUNT(event_type = 'enrollment') / COUNT(event_type = 'preview')`
- **Related Columns**: `event_type`, `course_id`, `course_name`
- **Why It Matters**: Measures how effectively course previews convert to paid enrolments — key product funnel metric
- **Update Frequency**: Weekly
- **Owner**: Product & Growth team

---

### Recency Score
- **Formula**: `MAX(purchase_date) per customer_id → (TODAY - MAX(purchase_date)).days`
- **Related Columns**: `days_since_last_purchase`, `customer_id`, `purchase_date`
- **Why It Matters**: Feeds churn risk models — customers with high recency scores need proactive re-engagement
- **Update Frequency**: Daily (recomputed on each pipeline run)
- **Owner**: Data Science / CRM team

## Task 3 — Ambiguous Columns & Resolutions

### Column: `flag_churn`
- **Original Ambiguity**: Does it mean "customer is currently churned" or "customer will churn in future" or "customer churned after this specific transaction"?
- **Resolved Meaning**: Binary indicator of whether the customer churned **within 90 days following this transaction** — a historical, backward-looking label
- **Business Interpretation**: Used as the target variable (`y`) when training ML churn prediction models — it labels past behaviour, not current state
- **Proposed Rename**: `has_churned_90d`
- **Risk If Misunderstood**: A team using this as a real-time active-churn flag would target already-lost customers with retention offers, wasting budget

---

### Column: `cust_segment`
- **Original Ambiguity**: Is this the market segment (B2B/B2C), the product tier (Basic/Pro/Enterprise), a geographic segment, or an internal sales territory?
- **Resolved Meaning**: Customer **market segment** (B2B, B2C, SMB) — the go-to-market category that determines the sales approach and contract type
- **Business Interpretation**: Directly informs pricing strategy, SLA commitments, and which sales team owns the account
- **Proposed Rename**: `market_segment`
- **Risk If Misunderstood**: Revenue analysis segmented by the wrong dimension produces misleading performance comparisons (e.g., comparing B2B vs. B2C when you think you're comparing product tiers)

---

### Column: `trnx_amt`
- **Original Ambiguity**: Is this the gross amount, net amount after discounts, the amount invoiced, or the amount actually collected?
- **Resolved Meaning**: Gross transaction amount in USD — the full price charged before any credits, refunds, or discount adjustments
- **Business Interpretation**: Represents recognised revenue at point of sale; should equal `invoice_amount` in the billing system
- **Proposed Rename**: `gross_transaction_amount_usd`
- **Risk If Misunderstood**: Using gross as net overstates revenue in financial reports; using net as gross understates discount impact

---

## Task 4 — Column Relationships

### Revenue per Customer (Customer Lifetime Value Proxy)
- **Definition**: `SUM(trnx_amt) GROUP BY customer_id` across all time periods
- **How It Matters**: Identifies high-value customers who should receive priority retention investment; enables tiered support and personalised upsell strategies
- **Example**: "Top 10% of customers by `trnx_amt` generate 52% of total platform revenue"
- **Related Columns**: `customer_id`, `trnx_amt`, `cust_segment`, `purchase_date`
- **Business Action**: High-value customers with high `days_since_last_purchase` are prime win-back targets

---

### Churn by Segment
- **Definition**: `SUM(flag_churn) / COUNT(customer_id) GROUP BY cust_segment`
- **How It Matters**: Reveals which market segments have the highest churn risk — allows segment-specific retention strategies rather than one-size-fits-all campaigns
- **Example**: "SMB segment has 28% churn rate vs 9% for B2B — SMB needs a dedicated customer success programme"
- **Related Columns**: `flag_churn`, `cust_segment`, `customer_id`
- **Business Action**: Segments with churn rate >20% trigger quarterly business reviews with CS leadership

---

### Revenue Velocity (30-Day Rolling Revenue)
- **Definition**: `SUM(trnx_amt)` over a rolling 30-day window, ordered by `purchase_date`
- **How It Matters**: Tracks sales momentum and early-warning trend signals before they appear in monthly reports; a 3-week revenue plateau often precedes a churn spike
- **Example**: "Monthly revenue velocity trending up 15% QoQ, driven by B2B segment enrolments in Cloud Computing category"
- **Related Columns**: `trnx_amt`, `purchase_date`, `cust_segment`, `category`
- **Business Action**: Velocity decline triggers a pipeline review with the sales operations team

---

### Funnel Conversion: Preview → Enrolment
- **Definition**: `COUNT(event_type='enrollment') / COUNT(event_type='preview') GROUP BY course_id`
- **How It Matters**: Measures how well each course's preview converts to paid enrolment — low conversion indicates poor course description, pricing mismatch, or wrong audience targeting
- **Example**: "Machine Learning Fundamentals has a 40% preview-to-enrolment rate vs 15% platform average — content and pricing are well-calibrated"
- **Related Columns**: `event_type`, `course_id`, `course_name`, `category`, `trnx_amt`
- **Business Action**: Courses with <10% conversion rate are flagged for content or pricing review
